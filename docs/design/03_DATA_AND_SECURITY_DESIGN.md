## 1. Purpose（目的）

本文書は、score-reader プロトタイプが扱うデータの種別・取り扱い方針、および著作権・外部サービス利用・秘密情報に関するセキュリティ設計仕様を定義し、実装・運用フェーズの基準とすることを目的とする。

score-reader はデータベースを持たないローカル実行 CLI ツールである。本文書は完成アプリの DB 設計としてではなく、プロトタイプ・技術検証フェーズのデータ取り扱い方針書として位置づける。

セキュリティ要求レベルは `02_REQUIREMENTS_DEFINITION.md` §5.2 に記載する。本文書の対象読者は、設計者・実装者・プロジェクトオーナーである。

---

## 2. Scope（対象範囲）

| 対象 | 内容 |
|---|---|
| 入力データ | score-reader が読み込む MusicXML ファイル |
| 出力データ | 標準出力に出力するテキスト形式・JSON 形式の検査結果 |
| テスト素材 | `prototype/tests/` 配下に配置する検証用 MusicXML |
| 外部 OMR サービス連携データ | 外部 OMR サービスへ送信する楽譜 PDF・画像（score-reader の入力生成過程で発生する） |
| 秘密情報・認証情報 | API キー・トークン・秘密鍵・個人情報の取り扱い方針 |
| 著作権・ライセンス | 楽譜素材および外部サービス利用に関する著作権・ライセンスポリシー |

## 3. Out of Scope（対象外範囲）

| 対象外項目 | 理由 |
|---|---|
| データベース設計（テーブル・ER図） | score-reader はデータベースを持たないローカル実行 CLI ツールである |
| ユーザー認証・認可設計 | ローカル実行ツールのためユーザー管理機能を持たない |
| ネットワーク通信設計 | score-reader 自体はネットワーク通信を行わない（外部 OMR サービス連携はツール外の操作） |
| クラウドストレージ・外部ストレージ設計 | プロトタイプフェーズでは外部ストレージを使用しない |
| アクセスログの集中管理 | プロトタイプフェーズでは対象外（TBD-001） |

## 4. Assumptions（前提条件）

本文書の内容が成立するために必要な前提は `01_REQUEST_DEFINITION.md` §4 を継承する。以下はデータ・セキュリティ設計フェーズで追加する前提を示す。

- score-reader はデータベースを持たない。データは「入力 MusicXML（読み取り専用）」と「標準出力（テキスト/JSON）」のみで完結する
- OMR 出力 MusicXML は「正解データ」ではなく「確認対象データ」として扱う。score-reader の検査結果も同様に確認対象であり、正確性の保証とは区別する
- 外部 OMR サービスへの楽譜送信は、score-reader の処理スコープ外（利用者が事前に行う操作）であるが、著作権・利用規約の観点から本文書で方針を定める
- 本文書の v0.1 日付は、移行元 Legacy Source（`legacy/MULTI_OMR_BASIC_DESIGN.md`）の初版コミット日（2026-06-04）を引き継ぐ

## 5. Definition Details（定義内容）

### 5.1 Data Scope（データ種別・スコープ定義）

score-reader はデータベースを持たないため、エンティティ定義・ER 図は対象外とする。理由: ローカル実行 CLI ツールであり、データは実行ごとにオンメモリで処理され、ファイルとして永続化しない。

代わりに、score-reader が扱うデータ種別を以下に整理する。

| データ種別 | 発生タイミング | 保存先 | 取り扱いの特性 |
|---|---|---|---|
| 入力 MusicXML | score-reader 実行時 | ローカルファイルシステム（利用者管理） | 読み取り専用・非破壊。score-reader は変更しない |
| 出力テキスト（検査結果） | score-reader 実行時 | 標準出力のみ | ファイル保存は利用者がリダイレクトで行う |
| 出力 JSON（検査結果） | score-reader 実行時（`--json` 指定時） | 標準出力のみ | 同上 |
| テスト素材 MusicXML | 開発・検証時 | `prototype/tests/`（リポジトリ管理） | パブリックドメイン楽譜に限定 |
| 楽譜 PDF・画像（外部 OMR 入力） | 利用者が外部 OMR サービスを利用する際 | 利用者環境・外部OMRサービス | score-reader の処理スコープ外。著作権・利用規約の確認が必要 |

**OMR 出力 MusicXML の位置づけ**

OMR が出力した MusicXML は「正解データ」ではなく「確認対象データ」である。score-reader の検査結果（警告・異常の有無を含む）も同様に確認対象であり、正確性の保証とは区別する。`[WARN]` / `[ANOMALY]` が 0 件であっても、MusicXML の完全無欠を保証しない。

### 5.2 Input / Output Data Definitions（入力・出力データ定義）

テーブル定義は対象外。理由: score-reader はデータベースを持たない。代わりに入出力データの仕様を定義する。

#### 入力データ（Input MusicXML）

| 項目 | 内容 |
|---|---|
| 形式 | MusicXML ファイル（`.musicxml` 等、`music21.converter.parse` が対応する形式） |
| 指定方法 | コマンドライン第 1 引数（絶対パス・相対パスいずれも可） |
| 件数 | 1 実行 = 1 ファイル |
| 取り扱い | 読み取り専用。score-reader は入力ファイルを変更・削除・複製しない |
| 著作権 | 利用者が著作権状況を事前に確認する責任を負う（§5.4 参照） |

#### 出力データ（Output: テキスト形式）

| 項目 | 内容 |
|---|---|
| 出力先 | 標準出力（stdout）のみ |
| 形式 | 人間可読テキスト（デフォルト） |
| ファイル保存 | score-reader は出力ファイルを生成しない。保存は利用者のリダイレクト操作に委ねる |
| 含まれる情報 | 検査結果のみ。入力ファイルのパス情報を除き、利用者の個人情報・秘密情報を含めない |

#### 出力データ（Output: JSON 形式）

| 項目 | 内容 |
|---|---|
| 出力先 | 標準出力（stdout）のみ（`--json` フラグ指定時） |
| 形式 | 構造化 JSON |
| ファイル保存 | score-reader は JSON ファイルを生成しない。保存は利用者のリダイレクト操作に委ねる |
| フィールド定義 | `02_REQUIREMENTS_DEFINITION.md` §5.1 JSON 出力フィールド定義 参照 |

#### テスト素材（Test Data）

| 項目 | 内容 |
|---|---|
| 配置場所 | `prototype/tests/` |
| 著作権条件 | **パブリックドメイン楽譜に限定する**（§5.4 参照） |
| 禁止事項 | 著作権保護された楽譜 PDF・MusicXML・画像をリポジトリに含めない |

### 5.3 Data Access and Role Design（データアクセス権限・ロール設計）

score-reader はシングルユーザーのローカル実行 CLI ツールであり、認証・認可機能を持たない。データアクセス権限はローカルファイルシステムの OS 権限に委ねる。

| Role Name（ロール名） | Accessible Data / Permitted Operations（アクセス可能なデータ / 操作範囲） |
|---|---|
| 利用者（CLI 実行者） | 入力 MusicXML の読み取り（Read only）。標準出力の参照 |
| score-reader プロセス | 入力 MusicXML の読み取りのみ。ファイルの書き込み・削除・派生ファイル生成は禁止 |
| 開発者 | `prototype/tests/` 配下のテスト素材の追加・更新（パブリックドメイン楽譜に限定） |

### 5.4 Personal and Confidential Data Policy（個人情報・機密データ・著作権の取り扱い方針）

#### 個人情報

score-reader は利用者の個人情報を収集・保存・送信しない。出力（テキスト/JSON）に個人情報を含めない設計とする。

#### 著作権保護データ（Copyright Policy）

楽譜データの著作権については以下の方針を定める。

| 方針 | 内容 |
|---|---|
| リポジトリへの登録禁止 | 著作権保護された楽譜 PDF・MusicXML・画像・その他楽譜素材を公開リポジトリ（GitHub 等）へ登録しない |
| テスト素材の制限 | `prototype/tests/` 配下に配置するテスト素材は**パブリックドメイン楽譜に限定する** |
| MusicXML メタデータの確認 | MusicXML ファイルには作曲者名・編曲者名・著作権者名・演奏者名等のメタデータが含まれる場合がある。個人情報・権利者情報を含む MusicXML は、公開リポジトリへ登録する前にメタデータの除去または公開可否の確認が必要 |
| 利用者の責任 | 利用者が score-reader に入力する MusicXML の著作権状況は、利用者が事前に確認する責任を負う |
| 外部 OMR サービス利用時 | 外部 OMR サービスへ楽譜 PDF・画像を送信する場合は、当該サービスの利用規約および著作権条件を事前に確認すること |
| 判断基準の明示 | 「パブリックドメインか否か」の判断は、著作権保護期間の満了・著作者による明示的な権利放棄等を根拠とする |

#### 秘密情報・認証情報（Confidential Data Policy）

| 禁止事項 | 対象 |
|---|---|
| ソースコードへの記載禁止 | API キー・トークン・秘密鍵・パスワード・個人情報 |
| Git 管理対象への記載禁止 | 同上（`.env`・設定ファイル・コメントを含む） |
| ログ・標準出力への出力禁止 | 同上（検査結果への混入を禁止） |
| リポジトリへの登録禁止 | 著作権保護素材・秘密情報を含む設定ファイル |

秘密情報が必要な場合は環境変数または `.gitignore` 管理のローカルファイルを利用すること。ただし現プロトタイプフェーズでは外部サービス連携を持たないため、API キー等は不要である。

#### 外部 OMR サービスデータポリシー（External Service Data Policy）

score-reader 自体は外部ネットワーク通信を行わない。しかし、入力 MusicXML の生成過程で利用者が外部 OMR サービス（Newzik 等）を利用する場合、以下の方針を適用する。

| 方針 | 内容 |
|---|---|
| 利用規約の事前確認 | 外部 OMR サービスへ楽譜を送信する前に、当該サービスの利用規約・プライバシーポリシーを確認する |
| 著作権条件の確認 | 送信する楽譜の著作権状況と、外部サービスの利用条件（送信データの二次利用・学習利用等）を確認する |
| 精度保証なし | 外部 OMR サービスの出力 MusicXML は確認対象データであり、正解データとして扱わない |

### 5.5 Encryption, Masking, and Logging Policy（暗号化・マスキング・ログ取得方針）

#### データ保持・保存方針（Data Retention / Storage Policy）

| データ種別 | 保持方針 |
|---|---|
| 入力 MusicXML | 利用者のローカル環境で管理。score-reader はコピーを作成しない |
| 出力テキスト / JSON | 標準出力のみ。保存が必要な場合は利用者がリダイレクトで対応。保存期間は利用者に委ねる |
| テスト素材 MusicXML | リポジトリに含める場合はパブリックドメインに限定。著作権保護素材はリポジトリに含めない |
| 実行ログ | プロトタイプフェーズではログファイルを生成しない |

#### 暗号化・マスキング・ログ取得

| Type（種別） | Target（対象） | Policy / Method（方式・方針） |
|---|---|---|
| Encryption（暗号化） | 入力 MusicXML・出力データ | 本文書では対象外。理由: ローカル実行ツールであり、データ暗号化は OS のファイルシステム保護に委ねる |
| Masking（マスキング） | 秘密情報 | ソースコード・出力・ログに秘密情報を含めないことで対応。マスキング処理は実装しない |
| Logging（ログ取得） | 実行ログ | プロトタイプフェーズでは対象外。理由: 標準出力への検査結果出力のみとし、ログファイルを生成しない（TBD-001） |

### 5.6 Security Design Specifications（セキュリティ設計仕様）

セキュリティ要求レベルは `02_REQUIREMENTS_DEFINITION.md` §5.2 に記載する。

#### セキュリティ設計仕様

| Type（種別） | Design Specification（設計仕様） |
|---|---|
| Authentication（認証） | 対象外。理由: ローカル実行ツールであり、ユーザー認証機能を持たない |
| Authorization（認可） | 対象外。理由: ユーザー管理機能を持たない。OS のファイルシステム権限に委ねる |
| Access Control（権限管理） | score-reader プロセスは入力 MusicXML の読み取りのみ許可。書き込み・削除・派生ファイル生成は禁止 |
| Communication（通信） | score-reader 自体はネットワーク通信を行わない。外部 OMR サービスの利用は score-reader のスコープ外（利用者責任） |
| Data Storage（データ保存） | ファイルを永続保存しない。入力は読み取り専用、出力は標準出力のみ |
| Data Disposal（データ廃棄） | score-reader が生成するデータはない（標準出力は OS が管理）。テスト素材の廃棄はリポジトリの `git rm` 操作で行う |
| Personal Data Protection（個人情報保護） | score-reader は個人情報を収集・保存・送信しない。出力に個人情報を含めない |

#### セキュリティリスクの整理（Security Risks）

| リスク | 内容 | 対策方針 |
|---|---|---|
| 著作権保護楽譜のリポジトリ混入 | 著作権保護素材が誤ってリポジトリに登録される | テスト素材はパブリックドメインのみ許可。レビュー時に確認する |
| 外部 OMR サービスへの著作権楽譜送信 | 著作権保護楽譜を無断で外部サービスへ送信してしまう | 送信前に利用者が著作権状況・利用規約を確認する運用ルールを周知する |
| API キー等の秘密情報のリポジトリ混入 | API キー・トークン等がコード・設定ファイルに含まれてしまう | プロトタイプフェーズでは外部 API 連携なし。将来フェーズでは環境変数管理を義務付ける |
| OMR 出力の誤信 | OMR 出力を正解として扱い、誤認識を見逃す | score-reader の出力に「確認対象データ」「完全無欠を保証しない」旨の注記を必ず含める（NFR 要件） |
| MusicXML メタデータの個人情報・権利者情報混入 | 作曲者名・著作権者名等を含む MusicXML が誤ってリポジトリに登録される | リポジトリ登録前にメタデータを確認する。個人情報・権利者情報が含まれる場合は除去または公開可否を確認する |

## 7. Handoff to Detail Design（詳細設計への引き継ぎ）

アーキテクチャ設計（`05_ARCHITECTURE_DESIGN.md`）・実装フェーズへ引き継ぐ主要事項を示す。

1. **非破壊仕様の徹底**: 入力 MusicXML ファイルを変更・削除・複製しないこと。実装レベルで読み取り専用アクセスのみ許可すること（§5.3 参照）。

2. **秘密情報の混入防止**: API キー・トークン・パスワードをソースコード・標準出力・ログに含めないこと。プロトタイプフェーズでは外部 API 連携がないため発生しないが、将来フェーズへの引き継ぎ事項として記録する（TBD-001）。

3. **テスト素材の著作権確認**: `prototype/tests/` に追加するすべての素材がパブリックドメインであることを追加前に確認すること（§5.4 著作権保護データ 参照）。

4. **OMR 出力の誤信防止の出力組み込み**: 検査結果に「OMR 出力は確認対象データであり正解ではない」「完全無欠を保証しない」旨の注記を含めること（§5.6 セキュリティリスク 参照）。
