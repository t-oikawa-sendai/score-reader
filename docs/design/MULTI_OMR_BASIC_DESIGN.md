# OMR サービス概要・精度

本書は、楽譜 PDF を MusicXML へ変換する OMR サービス・ツールの概要、精度・誤認識傾向、および複数 OMR 結果の比較が必要な理由を整理する。

## OMR サービスの概要

OMR（Optical Music Recognition）は、楽譜 PDF や画像から MusicXML 等の機械可読形式へ変換する処理である。

score-reader が扱う前提フローは次のとおりである。

```text
原本 PDF
  ↓
OMR サービス / OMR ツール
  ↓
MusicXML
  ↓
MuseScore 等で開き、人間が確認・修正
```

| 処理 | 担当 |
|------|------|
| 原本 PDF から MusicXML を生成する | 外部 OMR サービスまたは OMR ツール |
| MusicXML を開いて確認・編集する | MuseScore 等の外部楽譜編集ソフト |
| 最終的な正誤判断 | 人間（原本 PDF との照合） |

### 現行利用中: Newzik

利用者ヒアリングで確認した現行運用は次のとおりである。

```text
原本 PDF → Newzik → MusicXML → MuseScore → 人手で修正
```

Newzik は現行利用中の OMR サービスである。原本 PDF を読み込ませて MusicXML を生成し、MuseScore で開いて確認・修正する運用が行われている。

### その他の OMR 候補

楽譜 PDF を MusicXML へ変換できるサービス・ツールは Newzik 以外にも存在する。プロジェクト文脈で比較候補として言及されている例は、Audiveris、ACE Studio 等である。

いずれのサービス・ツールも、現時点で生成された MusicXML をそのまま完成版として扱える段階には至っていない。

## OMR サービスごとの特徴（整理上の観点）

詳細なベンチマーク結果は本リポジトリでは保持していない。以下は、運用・検証から整理した観点である。

| 観点 | 内容 |
|------|------|
| 入出力 | 原本 PDF（または画像）を入力とし、MusicXML を出力する |
| 表現差 | 同一原本でも、サービスごとにパート名、声部番号、休符補完、記号、XML 順序が異なることがある |
| 得意・不得意 | サービスごとに認識精度と得意分野が異なる |
| 移調情報 | 移調楽器の記載を欠落させる場合がある |
| 公式精度保証 | 本リポジトリが参照する Newzik の参考値は、利用者ヒアリングによる体感値であり、公式保証値ではない |

## 精度・誤認識傾向

### プロトタイプ検証と OMR 精度の関係

プロトタイプ（`verify_score.py`）による実証の結果、既存 OMR サービスが生成する MusicXML には、現時点で生成精度に大きな課題が残っていることが確認された。この結果は、事前の指摘を裏付けるものである。

### Newzik の参考値（利用者ヒアリング）

現行運用で Newzik が生成する MusicXML について、利用者ヒアリングで得られた体感上の参考値は次のとおりである。

| 対象 | 利用者体感による参考値 |
|------|----------------------:|
| 簡単な楽譜 | 約 95% |
| 難しい楽譜の基本的な音符の高さ・長さ | 約 70% |
| 細かいテキスト指示、臨時記号、アクセント等の音楽記号、多声部記譜など | 30% 未満の場合がある |

これらは利用者ヒアリングによる参考値であり、score-reader による計測結果や、Newzik が公式に保証する精度ではない。

### 誤認識が発生し得る要素

| 要素 | 問題例 |
|------|--------|
| 音符 | 音高、音価の誤認識 |
| 臨時記号 | フラット、シャープ、ナチュラルの誤認識・欠落 |
| 休符 | 休符種別の誤認識 |
| 複数小節休符 | 8 小節休符を 1 小節休符として扱う |
| 小節番号 | 欠落、重複、連番崩れ |
| 拍子・調号 | 欠落、位置ずれ |
| テンポ | 欠落 |
| 強弱記号 | 欠落 |
| アクセント等の音楽記号 | 欠落、誤認識 |
| 細かいテキスト指示 | 欠落、誤認識 |
| リハーサルマーク | 欠落、位置ずれ |
| タイ・スラー | 欠落、接続先誤り |
| 連符・装飾音符 | 構造誤認識 |
| 多声部記譜 | 表現構造の誤認識（1 本の五線譜に 2 旋律以上が重なる場合を含む） |
| 打楽器譜 | 表現構造の誤認識 |

### 問題の整理

- MusicXML 形式そのものが原因 → **誤り**（形式は OMR 出力の受け皿である）
- OMR 認識結果に誤認識・欠落が混入する → **正しい**（現時点の OMR 精度の問題）

### 作業負荷の参考

難しい楽譜では、OMR 出力を部分修正するだけでは済まず、MuseScore 上で音符を一つずつ人手で入力し直す場合がある。利用者ヒアリングでは、1 楽譜のデータ化に約 50 時間を要するケースがある。

## 複数 OMR 比較が必要な理由

### 単一 OMR だけでは不足する

```text
原本 PDF → 単一 OMR → MusicXML → そのまま採用
```

この方法では、OMR 由来の誤認識や欠落を見逃す可能性がある。

- OMR ごとに認識精度と得意分野が異なる
- 同じ譜面でも認識結果が異なる
- 単一結果だけでは、誤認識か正解かを判断できない
- MusicXML 内部整合性が正常でも、原本 PDF と異なる可能性がある

### 複数 OMR 比較の位置づけ

同一の原本 PDF を複数の OMR サービスまたはツールで MusicXML へ変換し、結果を比較することで、一致箇所と不一致箇所を切り分け、人間が確認すべき範囲を絞り込める。

複数 OMR の結果が一致していても、同じ原本上の曖昧さにより同じ誤りを出している可能性がある。一致結果だけを正解と断定してはならない。最終判断には原本 PDF との照合が必要である。

### MusicXML 単体では確定できない問題

| 問題 | 理由 |
|------|------|
| どの OMR 結果が正しいか | 原本 PDF を見ないと確定できない |
| 欠落した音符の正解 | MusicXML だけでは復元不能 |
| 複数小節休符の正確な数 | OMR 間差分だけでは断定不能 |
| タイ・スラーの正しい接続 | 表現意図を含むため、人間による原本照合が必要 |
| 連符・装飾音符の正解 | 原本照合が必要 |
| 多声部の正しい構造 | OMR 間の単純比較では不足 |
| 打楽器特殊記譜 | 楽器固有の解釈が必要 |
| 複数 OMR 一致時の正しさ | 同じ誤認識が起きる可能性がある |

## 完全自動化が困難な技術要因

score-reader は完全自動化を放棄するものではない。現時点で正確性を担保できる範囲を限定し、技術的に困難な要因を記録する。

1. **音高判定の不確実性** — 加線、符頭位置、調号、臨時記号、オクターブ違いにより、OMR 結果だけでは常に正しい音高を判定できない
2. **音価・リズム判定の不確実性** — 符尾、連桁、付点、連符、休符の認識誤りにより、小節内の拍数が崩れる可能性がある
3. **声部分離の不安定性** — 同一譜表内の複数声部において、上声・下声・休符補完・声部番号の扱いが OMR ツールごとに異なる可能性がある
4. **和音構成音の欠落・過検出** — 重なった符頭、内声部、同時発音の解釈により、和音の一部欠落や余分な音の追加が発生する可能性がある
5. **タイ・スラー・記号類の解釈差** — タイとスラーは見た目が近く、開始・終了位置、対象音符、小節またぎの扱いが不安定になりやすい
6. **小節対応ずれの連鎖** — 小節線、反復記号、アウフタクト、複縦線などの扱い差により、1 箇所の小節ずれが以降の比較全体に影響する可能性がある
7. **MusicXML 表現差** — 同じ楽譜内容でも、OMR ツールごとに表現が異なる可能性がある
8. **複数 OMR 間で同じ誤認識をする可能性** — 2 つ以上の OMR 結果が一致していても、同じ誤りを出している可能性がある

## score-reader による確認作業削減効果の概算

| 譜面タイプ | OMR結果の想定品質 | score-reader が支援できる範囲 | 人間確認の残量目安 | 作業削減率の目安 | 備考 |
|---|---:|---:|---:|---:|---|
| 簡単な単旋律・単一パート譜 | 高い | 大きい | 20〜40% | 60〜80% | 小節対応・音価検査が成立しやすい |
| 一般的な単一パート譜 | 中〜高 | 比較的大きい | 30〜50% | 50〜70% | 臨時記号・スラー・記号類は要確認 |
| 一般的なピアノ譜・合唱譜 | 中 | 中程度 | 40〜60% | 40〜60% | 声部・和音・歌詞・記号で確認箇所が増える |
| 多声部・連符・装飾音が多い譜面 | 低〜中 | 限定的 | 60〜80% | 20〜40% | 比較不能・要確認が多くなる |
| 打楽器特殊記譜・現代音楽的記譜 | 低い | 小さい | 70〜90% | 10〜30% | OMR自体の構造化が不安定 |
| OMRが大きく崩れた譜面 | 極めて低い | ほぼなし | 90〜100% | 0〜10% | score-reader ではなく再OMR・手入力判断が必要 |

- 上記の割合は、score-reader による実測値ではなく、設計段階での作業削減効果の概算である。
- 譜面の難易度、OMRサービスの品質、MusicXMLの構造崩れ、小節対応付けの成否により変動する。
- 作業削減率は「完成版を自動生成できる割合」ではなく、「人間が重点確認すべき範囲をどの程度減らせるか」を示す。

## 著作権・外部サービス利用の注意

- 著作権保護された譜面を GitHub 等の公開リポジトリへ登録しない
- 外部 OMR サービスへ譜面を送信する場合は、利用規約と著作権条件を確認する
